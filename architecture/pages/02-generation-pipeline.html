Episode generation pipeline and quality gate

How every episode is planned, written, checked, voiced and published by the drop time, with a fallback that never misses a morning.

Reviewed twice, revised 2026-11-06. Both reviews ran, every finding was applied, and the text was reconciled with the 2026-10-23 decisions and the decision records (document 10) on 2026-11-06.

In one paragraph

One durable workflow, episode/produce, runs every episode of every kind through the same steps (PRD-v2 6.1). Each step is code around at most one model call, with a fixed JSON output schema, a timeout, a retry rule and a cost record. Code validators sit after the teacher and after the writer so that every numeric rule of the PRD (targets, new words, facts, cold open, scenes, throw, cast, name count, duration) is decided by code, not by the model that wrote the text. The expensive steps (teacher on an Opus-class model, writer on a Sonnet-class model) run through the Message Batches API at half price when the drop time is far enough away, and are cancelled and re-run at standard price when it is not; everything downstream runs at standard price because it is cheap and the chain must finish by the drop. The editor model is a second vendor; when that vendor is down the editor runs on a different Anthropic model class from the writer with a review flag, and never on code checks alone. Two voice vendors are wired behind one adapter with a pre-paired "understudy" voice per host, so a vendor outage becomes a one-line on-air announcement rather than a missed drop; learner-initiated voice swaps and renames go through the same announcement path. Word timings for the player come from one alignment path regardless of vendor. The return episode is planned and pre-written at day 5 of a gap, and the next unpicked idea is pre-written as text for learners who swap or who ask for a second episode (prewrite_extra), so an on-demand episode's first sound depends on one TTS render rather than a model chain. The first new episode of a learner-local day is the drop; the second and third (episode_kind = daily_extra, for the two_a_day and three_a_day plans) are made when the learner asks, through the same on-demand path, from the extra slots of the nightly plan, so no Opus call sits on that path either (ADR-05). Everything language-specific is read from two package kinds, packages/languages/<target>/ and packages/native/<lang>/, chosen by the learner's target_language and native_language (ADR-02); the pilot's packages are languages/en and native/ar. All glosses, timestamps, the word index, the call brief, the chat opener, the recap and the feed item exist before the episode is marked ready, which is what makes the word sheet open in under 300 ms and the dropped episode start in under 2 s.

The decisions

Section 1's table, one card per decision. "Rejected" is what was considered and turned down.

  1. D1

    One Inngest function episode/produce for every episode kind (daily, daily_extra, swap, return, pilot, sample, fallback, rehearsal, finale), parameterized by episode_kind and pricing_mode; two small sibling functions, ideas/refresh and return/plan [DECISION]

    Why One code path to test; the on-demand kinds differ only in deadlines and what is skipped; the two siblings exist because they run when no episode is being produced

    Rejected Separate pipelines per kind: three times the surface for a two-person team

  2. D2

    Batch API for teacher and writer only, with per-step cut lines (teacher result by drop minus 4 h, writer by drop minus 2 h 30) and a hard switch to standard pricing at drop minus 90 min (PRD-v2 3.2); batch TTS joins under the same mechanism (t_voice_cut = drop - 2 h) only if the week-1 turnaround test passes [DECISION]

    Why Teacher plus writer are about $0.15 of the estimate; batch halves them. The cut lines keep the 90-minute rule true even after rewrites and resyntheses

    Rejected Batch for the editor (unbounded turnaround within 24 h, saving in cents); standard everywhere ($0.07 to $0.10 a session lost for nothing)

  3. D3

    Teacher = Claude Opus 5.5 (claude-opus-5-5, adaptive thinking, output_config.effort="medium" on ordinary nights, "high" on the weekly-mix night and at season boundaries, 08 lever 10); writer and rewrites = Claude Sonnet 5.5 at effort medium; fitter tagging, sense selection, glosses, moderation and idea refresh = Claude Haiku 5.5 (idea refresh on Sonnet 5.5); editor = Gemini 3.8 Flash (second vendor) with Claude Opus 5.5 as the same-vendor fallback [DECISION, PRD-v2 14.1, 14.3; 08 4.7]

    Why Roster as specified. Opus 5.5 and Sonnet 5.5 cannot switch thinking off, so effort is the only cost control; Sonnet's default high adds thinking tokens on a creative task with no evidence of better scripts

    Rejected Opus for the writer (triples writer cost); same vendor for editor and writer by default (shared blind spots, PRD-v2 6.1 forbids it); Haiku as the editor fallback (08's first-draft row; too close to the writer's generation to out-read it; settled as Opus by ADR-11)

  4. D4

    Every model output is requested as structured JSON (output_config.format) against a schema in this document, validated by code before the next step; a schema-invalid or truncated result is retried once with the validator's errors appended, then the step is exhausted [DECISION]

    Why "Models propose, code decides" (PRD-v2 8.1). A malformed package is a retry, never a shipped episode

    Rejected Free-text packages parsed by regex as in Milestone 0: fragile at 200 learners

  5. D5

    Stable prompt prefix (system rules, host and Salma bibles, package rules, ban list) cached with one cache_control breakpoint at the 1-hour TTL; learners whose cut lines fall in the same 30-minute window are pooled into one batch so the prefix is warm; the cost table shows cached and uncached columns [DECISION]

    Why Bibles plus rules are 5,000 to 8,000 tokens read by every learner's writer and teacher; a one-request batch processed at a vendor-chosen time cannot rely on the 5-minute TTL

    Rejected Pricing the table on an assumed 90% hit rate (the first draft); re-sending the bibles uncached by design

  6. D6

    The fitter is code (lemmatizer, frequency list, word-bank probabilities, coverage formula) plus one Haiku call that tags which lines realize the grammar target, selects a sense id per content word, and marks chunks; rewrites go back to the writer [DECISION, PRD-v2 6.1, 6.2]

    Why Coverage is arithmetic and must be exact; structure realization needs a small model; rewriting is the writer's job so voice and story stay intact

    Rejected Haiku rewriting failing sentences (voice drift); regex-only target detection

  7. D7

    Editor checks 1, 2, 4 and the deterministic halves of 8 and 10 are code; checks 3, 5, 6, 7, 9, 11 and the semantic halves of 8 and 10 are the editor model with a fixed rubric and a JSON verdict; the decision rule is the PRD's: any remaining fail after one repair and one recheck is fallback [DECISION, PRD-v2 6.3]

    Why A code check never has an off day; the model is kept for judgments; the PRD's rule stands unless vetoed (section 10 asks, it does not pre-empt)

    Rejected Shipping taste-check fails with a review flag (the first draft; it re-decided a settled rule and would have shipped episodes failing check 9, which is law 4)

  8. D8

    Fallback episode is a real pipeline run with episode_kind=fallback (interest only, no facts, no arc, no callback), not a canned file; checks 1 to 5 and 10 block it, 6 to 9 and 11 are run and logged [DECISION, PRD-v2 6.3]

    Why It must still pass checks 1 to 5 and 10 against this learner's level, which a canned file cannot

    Rejected A pre-rendered generic episode per level: wrong level, wrong casting, breaks law 2

  9. D9

    Two TTS vendors wired from day one behind tts-adapter; each host voice has a paired understudy on the second vendor chosen in the blind test; failover is automatic for the rest of the day's production and sticky until Muath flips it back; every voice change (vendor failover, flip-back, learner swap, rename) is a row in pending_announcements that the next shipped episode must carry in its cold open, checked by code [DECISION, PRD-v2 7.1.3, 14.3, 15]

    Why "Second vendor within the same day's production" with no human in the loop at 02:00; "a host's voice never changes silently" covers learner-initiated changes too

    Rejected Manual failover; automatic flip-back; a silent rename

  10. D10

    Word timings always flow through one align step: vendor timestamps are accepted when the adapter returns them, otherwise forced alignment against the known script; the output schema is the same either way [DECISION, PRD-v2 6.1 step 5]

    Why The player, Huh?, sentence replay and the word-sheet audio cut depend on the timing schema, not on the vendor

    Rejected Vendor-specific timestamp handling in the client

  11. D11

    Audio re-listen uses the same batch verbatim recognizer as call re-transcription (the 10.14 winner) and diffs per line, scoring only the words that matter (targets, planted new words, the learner's name) plus a WER on lines with no proper noun; up to two resyntheses, each with a change (never the same request twice), then synonym rewrite or a transcript mark [DECISION, PRD-v2 6.4]

    Why One ASR adapter, one vendor contract; a deterministic TTS re-rendered with the same text is a no-op, so each attempt changes something

    Rejected Trusting alignment confidence alone; WER over whole lines (two recognizer slips on a proper noun from the learner's own language would fail every line)

  12. D12

    Gloss cache keyed (lemma, sense_id, native_lang) where sense_id is a row in a per-lemma senses table; the fitter's Haiku pass selects among existing senses and may propose a new one with a one-line definition that code de-duplicates by embedding (cosine over 0.9 merges); the per-episode word index is precomputed and shipped [DECISION, PRD-v2 5.7, 6.6]

    Why A meaning is not personal; the 300 ms budget allows no generation at tap time; a free-text key would fill the cache with near-duplicates

    Rejected Per-learner glosses; generation on tap; lemma#pos#gloss free-text keys (the first draft)

  13. D13

    Similarity check = embedding of the script compared in application code with the learner's last 20 script embeddings stored as float arrays in Postgres; no vector index; the embedding vendor is Google (already a processor for the editor), Voyage as the swap [DECISION, PRD-v2 6.5]

    Why Twenty dot products is a microsecond; the PRD reserves vector indexes for callback search; script text carries the learner's name and facts, so the vendor must be in 07's processor register, which excludes OpenAI

    Rejected pgvector for this; OpenAI embeddings (08's first-draft row; settled as Google by ADR-10)

  14. D14

    Series bible fiction (side characters, running jokes, places, arcs) is written by this pipeline when an episode ships, with a code cap of 5 non-dormant side characters; show canon from the learner's side is written by the analyst [DECISION, PRD-v2 7.4 to 7.6, 8.3]

    Why A character exists only once a learner has heard it; arcs advance only on shipped-and-played episodes

    Rejected The writer writing the bible directly

  15. D15

    On-demand first sound: the return episode is planned and pre-written as text at day 5 of a gap (return/plan), the next unpicked idea is pre-written as text in the nightly run for learners who have swapped before or who use the day's extra episodes (prewrite_extra, ADR-05), and every other on-demand kind splits scene 1 into its own writer call and voices it first; the first sound of a pre-written kind is one TTS render [DECISION, PRD-v2 3.6.3, 3.8.3, 9.1 trigger 4, 2.2 A6, 15; ADR-05]

    Why Under 30 s is a P0 budget stated three times; an Opus call cannot sit on the path; pre-writing text in batch costs about $0.055 per pre-written script and is spent only where a swap is likely

    Rejected Pre-writing and voicing all three ideas (PRD-v2 14.5 removed unused picks); accepting 45 s p95 for everything (the first draft)

  16. D16

    The sample episode (2.1) is episode_kind=sample on the same function with a stub learner model, a Haiku moderation pass on the three public answers, model checks 3, 5 and 10 on scene 1 before streaming, no article, no alignment, and Salma's closing line in the landing page's language (native/<lang> of the page, English by default) appended at mix; cost ceiling $0.05 enforced by step budget [DECISION, PRD-v2 2.1; ADR-02]

    Why Same code, a tenth of the work; the endpoint is public and the audio is forwardable, so the input is moderated and the output model-checked

    Rejected A separate marketing generator; code checks only on a public, hostile-input surface (the first draft)

  17. D17

    Human review is a review_items queue sampled monthly (every episode in Milestone 0 and the first beta week, 10 per learner per month after), read on an internal page that shows the learner's name replaced by a pseudonym; findings write ban-list entries and prompt notes through code [DECISION, PRD-v2 6.8]

    Why Findings must land as versioned config; the reviewer is a processor of personal data and sees the minimum

    Rejected Reviewer edits the prompt file; the reviewer sees the name

  18. D18

    Frequency list per target package = wordfreq for that language (English for the pilot target, as in the Milestone 0 checker; permissive license); a subtitle-corpus list as a swap behind languages/<target>/lexicon.frequency_list once licensing is settled [DECISION, PRD-v2 10.4; ADR-02]

    Why Ships week 1 with no license question

    Rejected Blocking week 1 on a corpus license

  19. D19

    Lemmatizer = the target package's spaCy model (en_core_web_sm for languages/en) loaded in the workflows process (Python, deterministic, offline); chunks from the package's formulaic-sequence list by longest match [DECISION, PRD-v2 10.4, 13; 01 D1; ADR-02]

    Why Code, not AI; the same process and library the assessment domain uses; no sidecar

    Rejected A TypeScript pipeline with a Python sidecar (the first draft's implied shape)

  20. D20

    Every step writes one pipeline_steps row with model, prompt version, token counts (including cache_read_input_tokens and stop_reason), vendor, cost and latency, and one trace span; cost per episode is the sum and is attributed to the learner [DECISION, PRD-v2 14.5]

    Why Cost tracing from the first learner is P0; cache hit rate and truncations are measured, not assumed

    Rejected Tracing only at the vendor dashboard level

  21. D21

    Two code validators, validate_plan (after the teacher) and validate_package (after the writer, before the fitter), plus check_duration after mix, enforce every numeric rule of PRD-v2 3.1.3, 5.1, 9.2.3, 9.5, 9.6, 2.3 and 7.1.3; a failed validation is one re-prompt with the violations listed, then the rule-based brief (plan) or a rewrite round with the violations as constraints (package) [DECISION, PRD-v2 8.1]

    Why "Models propose, code decides" needs deciding code for each rule, not a prompt line saying code will check

    Rejected Trusting the prompt's "hard rules" paragraph (the first draft)

  22. D22

    ideas/refresh: a small function triggered by session.after_pass.completed, follow_up.due and working_on.changed that re-validates tonight's three ideas against the fresh learner model, rewrites at most one (Sonnet 5.5, under 5 s) and re-emits ideas.ready [DECISION, PRD-v2 3.1.4, 9.1 triggers 1 and 3]

    Why The ideas were written last night; a moved interview or a follow-up coming due must change one idea before it is shown

    Rejected Rewriting all three (cost, and the learner may already have read them); showing stale ideas (the first draft)

  23. D23

    Episodes 2 and 3 of the day are episode_kind = daily_extra, made on the on-demand path when the learner asks (POST /v1/episodes/next → learner.extra_requested; api enforces episodes_today < plan.episodes_per_day), never autoplayed, never pre-voiced; the nightly teacher run plans every slot of the day (EpisodePlan.extras[], one set of targets per slot inside the 1 structure and 2 to 4 words rule), so the extra starts at the writer; an extra uses the next unpicked idea of the three; prewrite_extra pre-writes that episode's text in batch for learners who used an extra on 5 or more of the last 7 days or swapped in the last 30 [DECISION, ADR-04, ADR-05, concept-v2 law 11]

    Why Typical use is 50 to 60% of the allowance, so pre-voicing wastes about a third of the voice line; the on-demand path already meets the budget when the text exists

    Rejected Pre-producing the full allowance each night; a "next episode" feed; a second teacher run per extra (an Opus call on a 30 s path)

  24. D24

    Two package kinds: packages/languages/<target>/ (voices, recognizers, lexicon, structure inventory, calibration set, law words, correction words, crisis keywords, host bibles, format patterns, ban list, prompts, name rules) and packages/native/<lang>/ (interface strings, Salma's voice and lines, gloss language, "why" strings, sample close); every prompt loader, brief compiler and TTS request reads the pair from learners.{target_language, native_language}; prompts carry {target_language} and {native_language} placeholders; a target is produced only after languages/<target>/gate.yaml records a passed forone.langgate run, in which this domain's writing check is check 3 [DECISION, ADR-02, ADR-03]

    Why No launch pair means the pair is a per-learner fact; the two sides have different bars

    Rejected One package per pair (the first draft's single ar-en package); hard-coding English and Arabic until "later"

  25. D25

    Invisible teaching in the gate: the code half of check 10 matches languages/<target>/guard/correction_words.yaml (07's guard.check_output item 6, one file for the pipeline, the call and the chat) on every surface, and the model half fails any script, article, opener or recap in which a host corrects the listener explicitly, explains a rule or frames anything as a lesson; a recast inside the dialogue passes; hits are counted into 09's explicit_corrections_per_100_turns (ceiling 0) [DECISION, ADR-06, concept-v2 law 7]

    Why Law 7 must be enforced by code the way law 12 is; the pipeline is one of three places a correction could reach the learner

    Rejected A prompt line alone; keeping correction notes behind a flag

  2. Frequency-list license

    The beta ships languages/en on wordfreq (permissive). A subtitle-corpus list (SUBTLEX-style) is better for spoken English but its commercial terms need checking; the swap is configuration per target package.

  3. The announcement lines

    PRD-v2 7.1.3 requires a one-line on-air announcement for a vendor change, a voice swap, a rename and (this design) a name-respelling fix; the lines are authored content for the bibles' author (Part 18 #1): one line per host per kind, in character, in the target language, that says what changed without a reason that is a lie. Needed before build week 4 (2026-12-09).

  4. Relaxing two taste checks

    The design ships the PRD's rule: any check still failing after one repair means a fallback episode. If the beta's first week shows fallbacks driven mostly by checks 7 (not generic) and 11 (pitch test), the switch editor.soft_fail_ships can let those two, and only those two, ship with a review flag. Default off; this is a request to relax later, not a shipped default; checks 8, 9 and 10 can never be relaxed.

  5. The reviewers and the review budget

    See 10-decision-records §10 #11 (a paid native reader per target language, who also performs the gate's writing check). This domain's number: 10 episodes per learner per month at 100 learners is 1,000 reads a month, about 80 reviewer hours at 5 minutes each, before 09's cut.

  6. Name respelling picker on A5

    The client domain built a three-candidate picker reachable from A5 (06 4.2); this design feeds it three respellings rendered as hellos from name_rules/<native>.yaml and runs no audio verification in P0. Confirm the picker stays, or A5 shows only the hello with the first candidate and fixes go through Salma.

  7. Ideas language

    Ideas are written in the target language as show content (titles are show titles); the notebook, Today chrome and "why this episode" are in the learner's native language. Confirm, or ask for idea lines in the native language (one extra Sonnet call per plan, about $0.005).

  8. Pre-writing the next idea

    For learners who have swapped in the last 30 days or used an extra on 5 or more of the last 7, the next unpicked idea's script is pre-written as text each night (prewrite_extra, about $0.07 on those nights, $0.014 a session on average) so a swap or an extra plays in 10 to 14 s; ADR-05's "pre-produce episode 2" is realised as text only. Confirm, or set pipeline.prewrite_extra.min_swaps_30d and min_extras_7d to null and accept 25 s median for every swap and extra; or ask for voicing too for the heaviest users (about $0.20 a night more for them).

  9. On-demand p95

    See 10-decision-records §10 #15 (the 30 s median / 45 s p95 budgets). This domain's number: a learner's first swap or first extra, the pilot and the sample reach first sound in about 25 s median and 40 s p95 on 2026-12-23 (PRD-v2 15 says under 30 s with no percentile). Accept the p95, or fund the streaming writer in build week 5 (about 1.5 engineer-days, takes 5 to 8 s off the path).

  10. Processors that see scripts

    See 10-decision-records §10 #14 (processors to approve, with counsel). This domain's list: Google (editor and embeddings), the Anthropic models, the TTS and ASR vendors and the human reviewer see pseudonymized scripts with the learner's facts; the editor fallback on Claude Opus 5.5 is settled (ADR-11) and logged as same_vendor_edit.

  11. Export contents

    The export includes every episode's script, article, "why", summary and the series bible as text; produced audio is excluded by default (it is the show's rendering, the archive stays playable in the app). Confirm, or include the audio and accept exports of several hundred megabytes per season.

  12. The second target language

    English is the pilot target and the only one that must pass the gate before 2026-12-23 (ADR-03). Nothing in this pipeline is English-specific once languages/<target> exists, but a second target needs its own spaCy model, frequency list, structure inventory, bibles translated or re-authored, voices through the blind test and a native reader; about two engineer-weeks plus content. Decide whether a second target is a beta goal or a post-gate one.

    With this prior the coverage pass is arithmetically unreachable for any learner whose word bank is mostly unseen (every new learner for the first days, every sample and pilot).

    Where, evidence and fix

    4.5 Step 3, 'Prior for unseen words': p = sigmoid((size_est - rank) / (0.35 * size_est)) clipped to [0.02, 0.98]

    With this prior the coverage pass is arithmetically unreachable for any learner whose word bank is mostly unseen (every new learner for the first days, every sample and pilot). 1. Summary and the decisions in one table

2,922 words

One durable workflow, episode/produce, runs every episode of every kind through the same steps (PRD-v2 6.1). Each step is code around at most one model call, with a fixed JSON output schema, a timeout, a retry rule and a cost record. Code validators sit after the teacher and after the writer so that every numeric rule of the PRD (targets, new words, facts, cold open, scenes, throw, cast, name count, duration) is decided by code, not by the model that wrote the text. The expensive steps (teacher on an Opus-class model, writer on a Sonnet-class model) run through the Message Batches API at half price when the drop time is far enough away, and are cancelled and re-run at standard price when it is not; everything downstream runs at standard price because it is cheap and the chain must finish by the drop. The editor model is a second vendor; when that vendor is down the editor runs on a different Anthropic model class from the writer with a review flag, and never on code checks alone. Two voice vendors are wired behind one adapter with a pre-paired "understudy" voice per host, so a vendor outage becomes a one-line on-air announcement rather than a missed drop; learner-initiated voice swaps and renames go through the same announcement path. Word timings for the player come from one alignment path regardless of vendor. The return episode is planned and pre-written at day 5 of a gap, and the next unpicked idea is pre-written as text for learners who swap or who ask for a second episode (prewrite_extra), so an on-demand episode's first sound depends on one TTS render rather than a model chain. The first new episode of a learner-local day is the drop; the second and third (episode_kind = daily_extra, for the two_a_day and three_a_day plans) are made when the learner asks, through the same on-demand path, from the extra slots of the nightly plan, so no Opus call sits on that path either (ADR-05). Everything language-specific is read from two package kinds, packages/languages/<target>/ and packages/native/<lang>/, chosen by the learner's target_language and native_language (ADR-02); the pilot's packages are languages/en and native/ar. All glosses, timestamps, the word index, the call brief, the chat opener, the recap and the feed item exist before the episode is marked ready, which is what makes the word sheet open in under 300 ms and the dropped episode start in under 2 s.

3.2 Data flow (draw as a left-to-right pipeline with one feedback loop, one side store and two small side functions)

  1. A trigger event arrives (idea.chosen, learner.cutoff_reached, learner.extra_requested, learner.swap_requested, learner.return_detected, onboarding.intake_completed, sample.requested). Every trigger carries episode_id (01: day/next creates the day's rows in state planned, one per slot of plan.episodes_per_day (ADR-05); api inserts the row for the other kinds; every row is in state requested when its trigger fires). episode-producer starts with {learner_id, episode_kind, slot, episode_id, drop_at} and reads episodes.pick for the idea, overrides and learner text, and learners.{target_language, native_language, tz} for the packages.
  2. For a daily episode it waits for session.after_pass.completed of today's session only when the pick arrived within 15 minutes of the session's end (a cutoff trigger hours later does not wait), then calls briefs.compile('teacher', learner_id) on the learner-model domain to get TeacherInput (capped at 12,000 tokens, 04's contract).
  3. teacher-service returns EpisodePlan (targets, new words, dials, facts allowed, callback, ideas, arcs, weekly mix, why, and one extras[] slot per further episode the plan allows); validate_plan checks it; variety-service.rank_ideas orders the ideas; code derives the WriterBrief for the pick, including pending announcements and the article-length band. Stored as artifacts.
  4. writer-service returns EpisodePackage; validate_package checks its structure. Stored as artifact version 1.
  5. fitter returns FitterReport; on fail, the failing sentence ids and constraints go back to writer-service.rewrite; at most two rounds. Each rewrite is a new package version.
  6. variety-service computes rotation, ban hits and similarity; editor runs the code checks then the model checks and returns EditorVerdict; on fail, one writer-service.repair call, then one recheck; on a second fail of any check, the function restarts itself with episode_kind=fallback.
  7. voice-studio renders the rendering plan (scenes in parallel, article read-aloud, recap; the feed tag and the hello clips are cached), mixes sound design, check_duration measures the file, and align produces AudioManifest with word timings.
  8. relisten transcribes the rendered audio, diffs per line, triggers up to two resyntheses with a change each, then a synonym rewrite (non-target words) or a transcript mark.
  9. gloss-service fills cache misses and writes the WordIndex.
  10. publisher uploads every object, then in one transaction writes episodes.state=ready, the artifact rows, the feed_items row with publish_at=drop_at (or now for on-demand kinds), applies bible updates, clears carried announcements, records the format in format_history, stores the script embedding, and emits episode.ready.
  11. Side store: every step writes pipeline_steps (cost, latency, versions, cache reads, stop reason) and a trace span.
  12. Side functions: ideas/refresh runs between today's session and tonight's chat close and may re-emit ideas.ready; return/plan runs at day 5 of a gap and leaves a return episode in state prewritten; the nightly daily run's last step, prewrite_extra, leaves the next unpicked idea's episode in state prewritten for learners who swap or use extras; the row serves a swap or a daily_extra, whichever the learner asks for first.

Feedback loop: step 5 to step 4 (rewrites), step 6 to step 4 (repair), step 6 to step 1 (fallback restart), step 3 to step 3 (one teacher re-prompt on a validation fail), step 7 to step 4 (one last-scene rewrite on a duration fail). Side inputs: the target package languages/<target>/ (bibles, ban list, lexicon, inventory, voice pools, sound design, prompts, guard lists) and the native package native/<lang>/ (Salma strings and voice, gloss language, "why" strings, sample close) read by steps 3 to 9; the series bible read by 3 and 4, written by 10; pending_announcements read by 3, cleared by 10.

Coverage algorithm (code; PRD-v2 6.2), run separately for the script (surface ear) and the article (surface eye):

tokens   = lexicon.lemmatize(text); chunks = lexicon.chunks(tokens)
units    = merge chunks over their tokens (a known chunk counts as one unit)
scored   = units where not is_name and not is_number and lemma not in plan.new_words
p(u)     = word_bank.p_understood(u.lemma or u.chunk_id, surface)      // learner-model domain; prior from frequency rank when unseen
coverage = mean(p(u) for u in scored)                                    // running units, not types
sentence_score(s) = mean(p(u) for u in s)
failing  = sentences with sentence_score < target - 0.03 OR containing a unit with p < 0.5 that is not in plan.new_words,
           ordered by contribution to the shortfall, until the shortfall is covered (never more than 25% of sentences in one round)
pass     = coverage >= dials.audio_coverage (ear) / dials.text_coverage (eye)

Prior for unseen words (the learner-model domain owns it, 04 4.5.1; the shape is decided here because the fitter's pass rule depends on it, and 04 adopts it, section 9 item 3) [DECISION]:

p0(rank) = 0.98                                                  if is_function_word or rank <= 0.5 * size_est
         = clip(sigmoid((1.25 * size_est - rank) / (0.10 * size_est)), 0.02, 0.98)   otherwise
         = 0.02                                                  if rank is null (not in the list)

size_est is the word-check vocabulary size estimate or the B1 default of 3,000 families. The shape saturates: the first half of the learner's estimated vocabulary is as good as known, the probability is 0.92 at rank = size_est, 0.5 at 1.25 times it and under 0.1 at 1.5 times it. Self-checks the week-1 unit test asserts under the cold-start prior at size_est = 3000: a script made only of top-1,000 words scores 0.98; a script with 97% of running words in the top 3,000 and the rest at ranks 3,000 to 6,000 scores about 0.958 (passes the 95% default, and the 96% first-week dial makes the writer tighten it, which is intended); a script at 95% top-3,000 scores about 0.943 and fails. The first draft's shape (width 0.35, uncapped) peaked at 0.946 for rank 1, so no script could ever pass; the numbers above are [ASSUMPTION, tuned in week 2 on Milestone 0 "how much did you follow?" answers], the shape is not.

Reconciliation with the Milestone 0 checker (tools/coverage-checker.html, binary rank <= N or known): the server fitter under the cold-start prior lands 1 to 1.5 points below the checker's binary score at the same N for a script with a few words past N, and equal for a script inside N. The week-1 regression test on the 10 Milestone 0 scripts asserts: every script the checker passed at N = 3000 with 97.5% or more passes the fitter at the 96% dial; no fitter score is above the checker's; none is more than 1.5 points below. "Coverage accuracy" in the offline suite (4.14) is the fitter's prediction against the hand-checked coverage and the learners' "how much did you follow?" answers, not against the checker.

Decision rule (code, PRD-v2 6.3): any fail on any check is repair; after one repair and one recheck, any remaining fail on any check is fallback. For episode_kind=fallback, checks 1 to 5 and 10 block; 6 to 9 and 11 are run, logged and filed as review items but do not block (a fallback has no arc, facts or callback, so 9 passes by construction). Three fallbacks in 7 days for one learner emit pipeline.human_page. The config switch editor.soft_fail_ships exists, defaults to false, and can relax only checks 7 and 11 (section 10 item 5); it can never relax 8, 9 or 10.

On-demand kinds gate scene 1 before episode.streaming_started with code checks 1 (coverage of scene 1 only), 4 and 10 plus model checks 3, 5 and 10 on scene 1 (01's shell rule); the full gate runs on the whole package before the manifest flips to ready, and a fail there supersedes the streamed episode with a fallback the same way (the learner hears the scene change at a seam, never mid-line).

4.7 The variety system

  • Real input (6.5.1): plan.real_input must be non-null for daily episodes (checked in validate_plan); for a brand-new learner the pilot intake answers count.
  • Ban list: ban_list entries {kind: name|setting|plot|phrase, value, lemma_seq, added_from: review_finding_id, added_at}; code matches names and phrases by lemma sequence, settings and plots by keyword sets; the model handles paraphrased plots. Updated monthly from review findings (6.8); seeded from the Milestone 0 bible's BANNED block.
  • Format rotation: format_history last 10; the teacher's ideas and the writer's script.format (or the mapped format of a custom idea) must not make three in a row; validate_plan fails the plan, check 8 fails the package.
  • Similarity: embed-adapter.embed(script_text) (Google embedding model by default; Voyage as the swap; Milestone 0 scripts set the threshold [OPEN, Part 18 #10]); cosine against the learner's last 20 script_embeddings; above variety.similarity_threshold (0.85 start) the package is regenerated once with the nearest episode's summary added to the writer prompt as "do not resemble"; a second hit is an editor check-8 fail, which follows the PRD's repair-then-fallback path. Embedding vendor outage: variety exhaustion row in 4.2.
  • Surprise in the content: the teacher may mark one idea is_wildcard and may set arc.step=pick_up for a side character absent for 10+ episodes; the bible excerpt lists "dormant characters" for this.
  • Custom formats (6.5): format/map (4.3) maps "Tell Salma an idea" to the closest pattern; the writer is told the description wins on conflict; the fitter and the code checks are unchanged (level, targets and structure rules hold for every format).

4.9 Audio re-listen (PRD-v2 6.4)

asr-adapter.transcribe_batch(audio, {verbatim: true, word_timings: true}) with the 10.14 winner. Per line: align the ASR words to the script words (Levenshtein on lowercase tokens, script.names and the learner's name excluded from the alignment cost). A line fails if (a) any target word or planted new word is missing or substituted, or (b) the learner's name token is not Metaphone-equal to one of voice_casting.name.expected_asr_forms (both sides are the same English recognizer's Latin output, so the comparison is valid), or (c) for a line with no proper noun, word error rate is above 0.15, or (d) a word is repeated more than twice (vendor stutter). Failing lines are re-rendered alone and re-spliced by timing, each attempt with a change: the first attempt uses the alternate respelling for a name or a style tag for a plain word; the second uses the understudy voice for that line; never the same request twice (a deterministic TTS would return the same audio). Then, for a line whose failing word is not a target, name or new word, the writer's rewrite replaces that word with a synonym from the fitter's known list and the line is rendered once more; otherwise the line ships with relisten.marked_lines and the transcript shows the correct text (the player never shows the ASR text). Only lines that changed after a resynthesis are re-transcribed (08 lever 9). Cost: about 10 min of audio per episode on batch ASR.

4.10 Senses, the gloss cache and the word index (PRD-v2 5.7, 6.6)

senses holds one row per (lemma, sense_id) with a one-line English definition and its embedding. The fitter's Haiku pass selects a sense_id for each content lemma from that lemma's existing rows; when none fits it proposes {lemma, pos, definition_en} and gloss-service inserts it only if no existing sense of the lemma has cosine over 0.9 to the proposal (otherwise the nearest existing id is used). Key (lemma, sense_id, native_lang). On a miss: one Haiku call per batch of misses using the native package's gloss_prompt (parameterised by the target) returning {meaning, pos, register_note|null, example} with meaning and register_note in native_lang and example in the target language; schema-validated; stored with prompt_version. One cache per (target, native) pair, shared by every learner of that pair. Multi-word chunks are keyed by chunk_id the same way. A sampled 5% of new glosses and every new sense join review_items. Same function, pricing_mode=standard, these differences:
