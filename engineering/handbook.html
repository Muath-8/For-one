How the agent builds For one

Everything the coding agent needs that is not product, architecture or design: the repository, a free local setup, three environments, the pipeline with its AI review pass, tests first, operations without a rota, the vendors, the data rules, and what "done" means. Ten pages and four starter files, including the agent's own AGENTS.md, kept in the repository and edited like code. Muath approves every merge, migration, prompt change and production deploy.

The ten rules

If you read nothing else. Each one is the compressed form of a page below, and each has a check in CI, a job in Inngest or a role in the admin behind it.

Tests before codeEach acceptance criterion of a story is an automated test, committed failing, before the code that makes it pass.
Never invent architectureIf the canon does not answer, the agent stops and asks Muath with options and a recommendation; it does not guess and build.
Fakes by defaultNo real vendor is called in dev unless the story is about that vendor. Every fake call is still priced, so the cost of a change shows before it runs for real.
Prompts are codeA file, a version, an eval run, the review pass and Muath's approval. There is no prompt editor in the admin and there will not be one.
Synthetic learners everywhereDev, staging, cassettes, canaries and load tests use invented people. Real learners live in prod and nowhere else.
Learner text stays homeIds and enums may travel to Inngest, Sentry, Slack and the logs. Names, transcripts, facts and audio never do. Prompts reach Langfuse only with the opt-in.
Every promise is verified by a second jobDeletion windows are re-checked hourly by code that does not share the doer's bugs.
Every vendor call is a priced rowThrough the middleware, on the cost page, with a fallback and a degrade path in vendors.yaml.
Fallbacks first, then an alertYesterday's episode stays, the understudy voice takes over, the call becomes voice notes; then Muath is told, and a runbook says what to do next.
Muath approves what cannot be undone quietlyMerges to main, migrations, prompt and bible changes, production deploys. The agent holds no prod credential.

The path of a change

From the agent's branch to a learner's morning. Teal boxes are automated gates, including the independent AI review pass; the amber boxes are where Muath approves. The eval gate runs only when the diff touches something a model reads, and prints its cost before it spends it.

Three environments

No fourth. Backend preview environments were rejected for cost; a PR that needs a running backend is tested on staging under a Slack lock. Staging stays up from the pipeline phase on (about $180 a month, ADR-16).

Where learner data may go

The product holds a person's voice and the facts of their life. The home region holds everything at rest; the EU tools hold pointers; the model and voice vendors see only what their role needs, in transit, under the vendor's standard DPA. No development environment, and no agent session, ever holds any of it.

What the guard does with it

At 80% of the daily cap the system enters conserve (batch TTS forced, rewrites capped, canaries and pre-writes skipped; never a model swap, which is a flag a person flips, ADR-14). At 100% it enters halt: queued episodes finish, no new on-demand generation except return episodes, extras and swaps pause for the UTC day, calls are never cut, claims are never degraded. The stop line at $1.00 pages Muath and opens a 48-hour window for a costed plan. It never stops service.

What the learner sees

Nothing. No cost, no "heavy user" message, no throttle text. The allowance is the only learner-facing limit and it is a product rule, not a cost rule. Every vendor call is one row in vendor_calls, priced from a dated price book, reconciled monthly against each vendor's invoice.

The ten pages

Each page is a Markdown file in engineering/, written against the architecture documents, PRD-v3 and ADR-25, for the coding agent. The line under each title is the rule it carries that the architecture did not already state.

01

Repository layout

One monorepo, four deployables (web, api, workflows, call-worker), eight packages, one Python image with three entrypoints, naming rules, and where every prompt lives as a versioned file.

CarriesTwo package kinds (ADR-02): packages/languages/<target>/ for what a model sees about the target language, and packages/native/<lang>/ for interface strings, consent texts, Salma's voice and crisis resources.
02

Local development

A full day of the product on one machine in under an hour: docker compose, idempotent seeds with three synthetic learners, the fake vendors and how to record a cassette, every environment variable with its owner.

CarriesFake calls still write priced vendor_calls rows, so the cost page works in dev.
03

Environments and deployment

dev, staging, prod; Terraform with an S3 backend; Secrets Manager injected by task role; GitHub OIDC; the home region (eu-central-1); Muath's approval on every prod deploy, the computed release window, rollback, expand-then-contract migrations, and the drained call-worker replacement.

CarriesThe agent holds no prod credential; no long-lived AWS key exists for anyone.
04

CI and CD

The workflows, the checks on every PR, the AI review pass, the eval gate that runs by diff and prints its cost, Vercel previews, branch protection with Muath as the only approver, the nightly, and the release.

CarriesA PR's eval gate may not spend more than $25 without a label only Muath applies.
05

Testing strategy

Tests first: each acceptance criterion is a named test before the code. Five layers: unit, contract, end to end, audio and voice, model-output evals. The simulated caller, the scripted calls, golden sets from synthetic learners and open and volunteer clips, and the coverage checker ported into the fitter.

CarriesA recognizer is gated on error-preservation rate before word error rate, because speech-to-text smooths learner errors.
06

Observability and operations

Postgres as the metrics store, alerts as SQL with runbook links, the cost-per-session dashboard defined line by line, the six P1 families and the fallback that runs before each, operations without a rota (alerts to Muath, runbooks the agent runs when asked), and blameless postmortems.

CarriesA postmortem that produces only "be more careful" is sent back.
07

Vendor accounts and cost controls

The accounts Muath opens, keys per environment and the agent's capped dev keys, the vendor-side retention switches, spend caps, spend modes, the stop line, the outside facts that change costs and the monthly reconciliation.

CarriesOur cap is always lower than the vendor's cap, so ours fires first.
08

Coding standards and review

Python and TypeScript rules enforced by Ruff, Pyright and ESLint; PR shape; the ten rules for prompt changes; the eleven things the AI review pass checks in this product, laws first, and the separate security review for auth, keys, media URLs, the feed and deletion.

CarriesA model change is a prompt change and runs the same suites.
09

Data handling

Seven data classes, the promises the code keeps with their windows and verifying jobs, what the agent may look at (ids, never content) and what only Muath may read, with a reason; where data may go; consent; fixtures; research use; incidents.

CarriesNo real learner's data is ever a fixture, a prompt or a PR; the agent never reads learner content.
10

Definition of done

Checklists for a story (tests first), a prompt change, a release, and the launch of version 1 (every v1 story done; v1.1 may follow).

CarriesA story without a kill switch is not done.

These carry a contract, a card or the company's legal identity. Open each under a company email with two-factor on; the agent gets only scoped, capped keys through Secrets Manager, never a login. "By" is the release-plan phase in which the account is first needed.

The build order

No calendar dates (ADR-25.1). The agent works story by story in the dependency order of backlog/00-release-plan.md; each phase ends on an exit check, and version 1 launches once, publicly, when every v1 story passes and the launch checklist (page 10 §4) is green.

1 · Foundation. Repo, CI with the review pass, Terraform for staging in eu-central-1, events and the learner model's tables, keys, tracing and the price book, logging and alerts, the English package and its gate resultevery test render is a priced row
2 · Pipeline and the minimal call. Vendor tests on open and volunteer clips, vendors.yaml, the pipeline from teacher to publish on synthetic learners, the minimal call worker and the scripted calls; staging stays up from heretest episodes with measured cost
3 · Onboarding, Today, feed. A1 to A10 with Salma, email one-time code sign-in, Today, the player, the feed and the drop, consent and the age gatefirst spoken sentence under 5 min
4 · The full call and the after-session pass. Hold-to-talk, the word button, the governor, verbatim, the voice-note fallback, crisis, the analyst and memory keeper, the spend guardzero governor violations
5 · The first week's surfaces. The claim gate and weekly proof, the notebook, Controls, plans and Paddle checkouta proof built only from events
6 · Production and launch. Production from the same Terraform, a restore rehearsed, deletion and export verified, the self-review checklist approvedthe launch checklist is green

The only dates that matter are outside facts: Gemini's prices double on 1 January 2027, so the voice is chosen on post-doubling prices; Hume's voice APIs shut on 13 November 2026.
